Expand description

The test program model contains tests, test invocations, patterns, bins, etc. that have been extracted from a flow AST into a generic data structure that can be consumed by all tester targets.

Fields§

§tester: SupportedTester§tests: IndexMap<usize, Test>

Test objects, stored by their internal ID. These map to test instances for IG-XL and test methods for V93K.

§test_invocations: IndexMap<usize, Test>

Test invocation objects, stored by their internal ID. These map to test flow lines for IG-XL and test suites for V93K.

§test_instance_groups: IndexMap<String, Vec<usize>>

IG-XL test-instance group name to member test IDs.

§test_collection_items: IndexMap<usize, TestCollectionItem>

Collection item objects referenced by test methods and nested collection items.

§sub_tests: Vec<SubTest>

Tests can store a single limit, but if a test has multiple limits then they are represented as sub-tests

§patterns: Vec<Pattern>

All pattern references made in the test program, flows and pattern_collections make reference to these via their ID (their vector index number)

§variables: Vec<Variable>

All variable references made in the test program, flows and variable_collections make reference to these via their ID (their vector index number)

§flows: IndexMap<String, Flow>§pattern_collections: IndexMap<String, Vec<usize>>§variable_collections: IndexMap<String, Vec<usize>>§custom_data: IndexMap<String, String>

Generic key-value metadata for use by importers and exporters. Provides a place to store format-level data (version strings, schema tags, etc.) that does not fit the structured model fields. Processors ignore this field; it is for import/export tooling only.

pub fn set_test_attr( &mut self, id: usize, name: &str, value: Option<ParamValue>, allow_missing: bool, ) -> Result<()>

Set the value of the given test attribute. If the given ID refers to a test invocation then both the invocation and the test will be checked for a matching attribute. Currently, if no matching attribute is found then nothing happens. An error is returned if the test doesn’t exist or if the value is the wrong type for the given parameter. Calling with value = None will cause all existing settings for the given attribute to be removed.
